# M01 — Domain & seed data

**Goal:** the business core of OpsDesk exists as plain, fully tested Python: entities, the rules that govern them, and the ports through which the rest of the system will store and load them. Plus a SQLite adapter and seed data so later milestones have something real to work with.

**Estimated effort:** 2–3 sessions, in two parts. Commit after each part.

> **Focus note:** M01 is plain Python, so it is entirely 📖 / ⚙️: Claude Code implements it and explains it; you read it and answer the self-check questions in §8. Your own coding effort starts with the harness milestones (see `CLAUDE.md` → "What counts as 🎯").
- **Part A (📖 read):** core value objects, domain models, policies, ports, unit tests.
- **Part B (⚙️):** seed data, in-memory + SQLite repositories, repository contract tests, seed task.

**Learning objectives:**
- Keep business rules out of prompts and frameworks: *"deterministic first, model second"* (W1 L2, W4 L3). In later milestones the model will only **propose** actions; the functions written here **decide**.
- Return **explainable decisions** (a reason code, all triggered gates), not bare booleans (W3 L1).
- Practise ports & adapters: the domain defines *what* storage must do; persistence decides *how*.

**Course topics:** W1 L2 (verification, ownership), W3 L1 (approval gates, return every triggered gate, separation of duties), W4 L3 (plain Python for fixed rules).

## 2. Core types

### 2.1 `Money` (📖, done)

```python
@dataclass(frozen=True, slots=True)
class Money:
    amount: Decimal
    currency: Literal["VND"] = "VND"
```

Requirements:
- Construct from `int`, `str` or `Decimal`; **reject `float`** (raise `TypeError`).
- VND has no minor unit: the amount must be integral (`Money("1500.5")` raises `ValueError`).
- Negative amounts are rejected.
- Supports `+`, comparison (`<`, `<=`, ...) and `==` only with another `Money` of the same currency.
- `Money.zero()` helper.

> Why not just `Decimal`? Because in M07 provider prices arrive in USD. A currency field makes "added USD to VND" a crash instead of a silent wrong number.

### 2.2 Domain models (📖)

Pydantic v2 models, `frozen=True`. Changing state means returning a new instance (`model_copy(update=...)`), never mutating.

| Entity | Fields |
|---|---|
| `Tenant` | `id`, `name` |
| `Employee` | `id`, `tenant_id`, `full_name`, `email`, `department` (`Department` enum: `engineering`, `design`, `hr`, `finance`, `it`, `sales`), `roles: frozenset[Role]` (`employee`, `it_staff`, `it_manager`, `hr`, `finance`), `owned_software: frozenset[SoftwareId]` |
| `Ticket` | `id`, `tenant_id`, `reporter_id`, `assignee_id: EmployeeId \| None`, `title`, `description`, `category` (`hardware`, `software`, `access`, `network`, `security`, `other`), `priority` (`low`, `medium`, `high`, `critical`), `status` (`TicketStatus`, §3.2), `asset_tag: str \| None`, `created_at`, `updated_at` |
| `SoftwareItem` | `id`, `name`, `annual_cost: Money`, `restricted_to: frozenset[Department]` (empty = everyone), `requires_admin: bool` |
| `AccessRequest` | `id`, `tenant_id`, `requester_id`, `kind` (`software_licence`, `admin_rights`), `software_id: SoftwareId \| None`, `justification`, `status` (`pending_approval`, `approved`, `rejected`, `cancelled`), `decided_by: EmployeeId \| None`, `decided_at: datetime \| None`, `created_at` |

Model-level validation (invariants that must hold for *any* instance):
- Every `datetime` is timezone-aware.
- `Employee.roles` is never empty and always contains `employee`.
- `AccessRequest`: `kind == software_licence` ⇔ `software_id is not None`.
- `AccessRequest`: `decided_by`/`decided_at` are set **if and only if** status is `approved` or `rejected`.

### 2.3 Decisions (📖)

```python
class ReasonCode(StrEnum):
    OK = "ok"
    CROSS_TENANT = "cross_tenant"
    NOT_OWNER = "not_owner"
    # ... add the codes your policies need

@dataclass(frozen=True, slots=True)
class Decision:
    allowed: bool
    reason: ReasonCode
```

`AccessEvaluation` (result of §3.3):

```python
class AccessOutcome(StrEnum):
    AUTO_APPROVE = "auto_approve"
    NEEDS_APPROVAL = "needs_approval"
    REJECT = "reject"

@dataclass(frozen=True, slots=True)
class AccessEvaluation:
    outcome: AccessOutcome
    reasons: tuple[ReasonCode, ...]   # every triggered rule, in a stable order
```

> Why reason codes instead of `bool`? Later the same decision feeds the model (a safe message), the UI timeline, the audit log and the evaluation suite. A bare `False` tells none of them *why*.

## 3. Policies (📖)

All policies are **pure functions**: no I/O, no clock reads (time is passed in), no config reads (rules are passed in). Signatures are given; Claude Code writes the bodies and explains them.

### 3.1 Ticket visibility

```python
def can_view_ticket(actor: Employee, ticket: Ticket) -> Decision: ...
```

| # | Case | Expected |
|---|---|---|
| V1 | Actor from another tenant, **even if `it_manager`** | deny, `CROSS_TENANT` |
| V2 | Actor is the reporter | allow |
| V3 | Actor is the assignee | allow |
| V4 | Actor has `it_staff` or `it_manager`, same tenant | allow |
| V5 | Regular employee, not reporter/assignee | deny, `NOT_OWNER` |
| V6 | `hr` / `finance` role, not reporter | deny (business roles do **not** grant ticket access) |

Order matters: the tenant check comes **first**, so no other rule can override it.

### 3.2 Ticket lifecycle

```python
def transition(ticket: Ticket, to: TicketStatus, actor: Employee, now: datetime) -> Ticket: ...
```
Returns the updated ticket (new `status`, `updated_at = now`) or raises `InvalidTransition` / `NotPermitted`.

Statuses: `open`, `in_progress`, `waiting_on_user`, `resolved`, `closed`.

| From → To | Who may do it |
|---|---|
| `open` → `in_progress` | IT (`it_staff` / `it_manager`) |
| `in_progress` → `waiting_on_user` | IT |
| `waiting_on_user` → `in_progress` | IT or reporter |
| `in_progress` → `resolved` | IT |
| `resolved` → `closed` | IT or reporter |
| `resolved` → `in_progress` (reopen) | Reporter |
| `open` → `closed` (withdraw) | Reporter |
| anything else | `InvalidTransition` |

Also: actor must be in the ticket's tenant (`NotPermitted`); transitioning to the current status is `InvalidTransition`; `closed` is terminal.

> Tip: express the table as **data** (a mapping from `(from, to)` to the set of allowed actor kinds) rather than a chain of `if`s. The table above should be readable directly from your code.

### 3.3 Access-request evaluation

```python
@dataclass(frozen=True, slots=True)
class AccessRules:
    licence_review_threshold: Money          # e.g. Money(5_000_000)

def evaluate_access_request(
    requester: Employee,
    kind: AccessKind,
    software: SoftwareItem | None,
    rules: AccessRules,
) -> AccessEvaluation: ...
```

Rules:
1. **Reject** rules (any one → `REJECT`):
   - software is restricted to departments that don't include the requester's → `DEPARTMENT_RESTRICTED`
   - requester already owns the software → `ALREADY_OWNED`
   - `kind` and `software` disagree (licence without software, admin rights with software) → `INVALID_REQUEST`
2. Otherwise, **review** rules (collect **all** that apply → `NEEDS_APPROVAL`):
   - `kind == admin_rights` → `ADMIN_RIGHTS`
   - `software.requires_admin` → `ADMIN_RIGHTS`
   - `software.annual_cost >= threshold` → `HIGH_COST`
3. Otherwise → `AUTO_APPROVE` with `(OK,)`.

`reasons` must contain **every** triggered rule of the winning outcome, without duplicates, in a stable order (W3 L1: return all triggered gates, not just the first).

| # | Case | Expected |
|---|---|---|
| A1 | Cheap, unrestricted licence | `AUTO_APPROVE` |
| A2 | Cost **exactly equal** to threshold | `NEEDS_APPROVAL`, `HIGH_COST` |
| A3 | Cost one VND below threshold | `AUTO_APPROVE` |
| A4 | Expensive **and** requires admin | `NEEDS_APPROVAL`, both reasons |
| A5 | Admin rights request | `NEEDS_APPROVAL`, `ADMIN_RIGHTS` |
| A6 | Finance-only tool requested by engineering | `REJECT`, `DEPARTMENT_RESTRICTED` |
| A7 | Expensive tool already owned | `REJECT`, `ALREADY_OWNED` (reject wins over review) |
| A8 | Licence request with `software=None` | `REJECT`, `INVALID_REQUEST` |

### 3.4 Approval eligibility

```python
def can_decide(approver: Employee, request: AccessRequest) -> Decision: ...
def approve(request: AccessRequest, approver: Employee, now: datetime) -> AccessRequest: ...
def reject(request: AccessRequest, approver: Employee, now: datetime) -> AccessRequest: ...
```

| # | Case | Expected |
|---|---|---|
| P1 | `it_manager`, same tenant, pending request by someone else | allow |
| P2 | Approver from another tenant | deny, `CROSS_TENANT` |
| P3 | `it_staff` (not manager) | deny, `NOT_APPROVER` |
| P4 | Manager approving **their own** request | deny, `SELF_APPROVAL` (separation of duties) |
| P5 | Request not `pending_approval` | deny, `NOT_PENDING` |

`approve` / `reject` call `can_decide` and raise `NotPermitted` when denied; otherwise they return a new request with `status`, `decided_by`, `decided_at` set.

## 4. Ports (📖)

`src/opsdesk/domain/ports.py`, using `typing.Protocol`, **async** methods:

```python
class TicketRepository(Protocol):
    async def get(self, tenant_id: TenantId, ticket_id: TicketId) -> Ticket | None: ...
    async def list_by_reporter(self, tenant_id: TenantId, reporter_id: EmployeeId) -> list[Ticket]: ...
    async def save(self, ticket: Ticket) -> None: ...
```

Write equivalents for `EmployeeRepository`, `SoftwareRepository` and `AccessRequestRepository`.

Design rule: **every lookup is scoped by `tenant_id`**. There is no `get(ticket_id)` without a tenant. Tenant isolation is enforced by the shape of the API, not by remembering to filter.

> Why are ports in `domain` and not in `persistence`? Because the dependency must point inward: persistence depends on the domain's contract, never the reverse. This is exactly what the `layers` contract in `.importlinter` guarantees.

## 6. Repository contract tests (⚙️ write, 📖 understand)

`tests/contract/test_repositories.py` runs **the same tests** against the in-memory and the SQLite adapter (a parametrized fixture). Minimum cases:
- `save` then `get` returns an equal entity (round trip, including `Money` and timezone-aware datetimes).
- `get` with the right id but the **wrong tenant** returns `None`.
- `list_by_reporter` returns only that reporter's tickets in that tenant.
- Saving an existing id updates it (upsert).

> This is the pay-off of ports & adapters: any future adapter (Postgres, an HTTP API) must pass the same suite. Unit tests later can use the fast in-memory adapter with confidence that it behaves like the real one.

Windows note: close every SQLite connection before a test ends (use `async with`), otherwise `tmp_path` cleanup fails on Windows with "file in use".
