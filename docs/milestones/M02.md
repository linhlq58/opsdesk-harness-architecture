# M02 — Core contracts

**Goal:** the shared "language" of the harness exists before any agent code: who is asking (`Principal`, `RequestContext`), how every tool answers (`ToolResult` + error taxonomy), and how everything that happens is recorded (`Event` v1, event bus, sinks). From M03 on, every tool, agent, graph, UI panel and evaluator speaks these contracts and nothing else.

**Estimated effort:** 1–2 sessions.

> **Focus note:** M02 is plain Python, so it is entirely 📖 / ⚙️. Claude Code implements it and explains it; you read it and answer the self-check questions in §9. Your hands-on harness work starts in M03, where these contracts meet LangChain for the first time.

**Learning objectives:**
- Identity is built by the **server** and travels beside the conversation, never inside it (W1 L2, W2 L2, W3 L1).
- Every failure belongs to exactly one class of the error taxonomy, and that class decides retry, gate, UI and eval behaviour (W1, W2 L1, W3 L1).
- One event contract feeds SSE, local logs and evaluation; the course samples used five different ones (W1 L3–L4, W2 L3).

**Course topics:** W1 L2 (trusted runtime context), W1 L3–L4 (event contract, local events beside LangSmith), W2 L1 (controlled infrastructure errors), W2 L3 (versioned public event envelope, `seq`, namespaces), W3 L1 (scopes, redaction).

## 2. Principal & scopes (security)

### 2.1 `Principal`

```python
class Principal(BaseModel, frozen=True):
    tenant_id: TenantId
    user_id: EmployeeId
    department: Department
    roles: frozenset[Role]
    scopes: frozenset[Scope]
    groups: frozenset[str]        # ACL groups for RAG (M09–M10): role names + "dept:<department>"

def principal_for(employee: Employee) -> Principal: ...
```

- `principal_for` is the **only** place scopes and groups are derived. Nothing else constructs a `Principal` with hand-picked scopes (tests use `principal_for` on seed employees).
- `groups` example for Dung (finance): `{"employee", "finance", "dept:finance"}`. M09 will tag every KB chunk with allowed groups; M10 filters on them.
- A `Principal` contains no name, no email: it is safe to log and to put in traces.

### 2.2 Scopes

Scopes are **coarse**: "may this kind of user call this kind of tool at all?". Domain policies stay **fine-grained**: "may this user see *this* ticket?". A tool call needs both.

| Scope | `employee` | `it_staff` | `it_manager` |
|---|---|---|---|
| `ticket:read` | ✓ | ✓ | ✓ |
| `ticket:create` | ✓ | ✓ | ✓ |
| `ticket:update` | ✓ | ✓ | ✓ |
| `access:request` | ✓ | ✓ | ✓ |
| `kb:read` | ✓ | ✓ | ✓ |
| `asset:read` | | ✓ | ✓ |
| `access:approve` | | | ✓ |
| `report:read` | | | ✓ |

`hr` and `finance` add no scopes; they only add ACL groups. Scopes are cumulative over roles (union). The table lives as **data** in `scopes.py`.

> Why does an employee have `ticket:read` if they may only see their own tickets? Because the scope only opens the door to the tool; `can_view_ticket` (M01) then decides per ticket. Two layers, two questions.

### 2.3 Scope check

```python
def require_scope(principal: Principal, scope: Scope) -> Decision: ...
# allow, or deny(ReasonCode.MISSING_SCOPE)
```

## 3. RequestContext

```python
class Workload(StrEnum):
    CHAT = "chat"
    EVAL = "eval"
    REPORT = "report"

class RequestContext(BaseModel, frozen=True):
    principal: Principal
    request_id: RequestId     # one user turn; correlates events, traces, audit, ledger
    thread_id: ThreadId       # one conversation (LangGraph thread)
    workload: Workload
```

Rules (written in the module docstring):
- Built **once per request** by the server (M04 from the token; tests and CLI from `principal_for`).
- Passed to graphs and tools through **LangGraph runtime context** (M03), **never** placed in messages sent to the model and never filled from a model's tool arguments.
- `workload` separates chat spending from evaluation spending (M16) and lets the eval suite filter its own runs (M17).

## 4. ToolResult & the error taxonomy

### 4.1 Statuses and classes

```python
class ToolStatus(StrEnum):
    OK = "ok"
    EMPTY = "empty"
    NOT_FOUND = "not_found"
    INVALID = "invalid"
    DENIED = "denied"
    UNAVAILABLE = "unavailable"
    TIMEOUT = "timeout"

class ErrorClass(StrEnum):
    NONE = "none"            # ok, empty
    BUSINESS = "business"    # not_found, invalid
    POLICY = "policy"        # denied
    TRANSIENT = "transient"  # unavailable, timeout
```

The mapping is **data** (one dict), exposed as `ToolStatus.error_class` and `ToolStatus.retryable` (true only for `TRANSIENT`). `empty` is a success ("you have no open tickets"), not an error.

### 4.2 `ToolResult[T]`

```python
class ToolResult[T](BaseModel, frozen=True):
    status: ToolStatus
    data: T | None = None
    safe_message: str | None = None   # may be shown to the model and the UI
    error_code: str | None = None     # machine-readable, e.g. a ReasonCode value; for logs/evals
```

Invariants:
- `ok` → `data` is not `None`; `safe_message` and `error_code` are `None`.
- `empty` → `data` is `None` or an empty collection.
- Every error status → `data is None` and both `safe_message` and `error_code` are set.

Constructors: `ToolResult.ok(data)`, `.empty()`, `.not_found(msg, code)`, `.invalid(msg, code)`, `.denied(msg, code)`, `.unavailable(msg, code)`, `.timeout(msg, code)`.

`safe_message` never contains exception text, stack traces, SQL, file paths or other tenants' data. It is written for the model to read.

### 4.3 Budget is not a status

```python
class BudgetExceeded(Exception):
    """Raised before a model call when a budget would be exceeded (M16). Never retried."""
    scope: Literal["turn", "thread", "day"]
```

It is an exception, not a `ToolResult`, because it stops the **run**, not just one tool call.

### 4.4 Domain errors → ToolResult

```python
def result_from_domain_error(exc: DomainError) -> ToolResult[Never]: ...
def result_from_decision(decision: Decision) -> ToolResult[Never]: ...   # only for denied decisions
```

| Input | `status` | `error_code` |
|---|---|---|
| `InvalidTransition` | `invalid` | `"invalid_transition"` |
| `NotPermitted(reason=r)` | `denied` | `r.value`, or `"not_permitted"` |
| `Decision.deny(r)` | `denied` | `r.value` |
| any other `DomainError` | `invalid` | `"domain_error"` |

Only `DomainError` is mapped. Bugs (`KeyError`, `AttributeError`, ...) are **not** caught here; they must surface. This is the fix for the course sample that wrapped everything in `except Exception`.

Lives in `opsdesk.tools` because it is the tool layer's job; M03's tool wrapper calls it.

## 5. Event v1

### 5.1 Envelope

```python
class Event(BaseModel, frozen=True):
    schema_version: Literal["opsdesk.event.v1"] = "opsdesk.event.v1"
    seq: int                       # 0, 1, 2, ... within one request; ordering never relies on ts
    event_id: EventId
    ts: UtcDatetime
    request_id: RequestId
    thread_id: ThreadId
    namespace: tuple[str, ...]     # () = top level; ("helpdesk", "rag") inside a subgraph
    kind: EventKind
    payload: dict[str, JsonValue]  # validated against the payload model for `kind`
```

A `model_validator` checks `payload` against `PAYLOAD_MODELS[kind]`. A kind without a registered payload model is rejected ("not emitted yet"), so nothing untyped can slip out.

### 5.2 Kinds and payloads (M02 subset)

All kinds from architecture §6.3 are declared in `EventKind`. Payload models now:

| Kind | Payload fields |
|---|---|
| `run_started` | `workload`, `entrypoint` (e.g. `"cli"`, `"router"`) |
| `node_started` | `node` |
| `node_finished` | `node`, `duration_ms` |
| `token` | `text` (a streamed chunk), `agent` |
| `tool_started` | `tool`, `args` (redacted) |
| `tool_finished` | `tool`, `status: ToolStatus`, `duration_ms`, `error_code \| None`, `summary` (redacted, truncated) |
| `run_finished` | `status: completed \| blocked \| interrupted \| failed`, `duration_ms` |

`run_started` deliberately does **not** carry the user's message. Events describe *what happened*; content is either redacted or omitted.

### 5.3 Versioning rule (in the module docstring)

Within `v1` you may add kinds and **optional** payload fields. Renaming or removing a field, changing a type, or changing a kind's meaning requires `opsdesk.event.v2`. The UI, stored JSONL files and eval datasets depend on this.

### 5.4 Redaction

```python
def redact(value: JsonValue, *, max_chars: int = 500) -> JsonValue: ...
```

- Keys whose name contains `password`, `secret`, `token`, `api_key`, `authorization`, `cookie` → `"[REDACTED]"` (case-insensitive, recursive through dicts and lists). `token` here means a credential key name; it does not apply to the `token` **event kind**'s `text` field, which is handled by the caller.
- Email addresses and phone-number-like strings inside values → masked (`a***@acme.test`).
- Strings longer than `max_chars` → truncated with a `"…[+N chars]"` suffix.
- Pure function, returns a new value.

Redaction is applied by `RunRecorder` to `tool_started.args` and `tool_finished.summary` before an event is created, so **no sink ever receives unredacted tool data**.

## 6. Recording and delivering events

### 6.1 `RunRecorder`

One per request. It knows the `RequestContext`, a `Clock`, and the bus; it owns `seq`.

```python
class RunRecorder:
    def __init__(self, ctx: RequestContext, bus: EventBus, clock: Clock) -> None: ...
    async def emit(self, kind: EventKind, payload: Mapping[str, JsonValue], *, namespace: tuple[str, ...] = ()) -> Event: ...
    def child(self, *namespace: str) -> "RunRecorder": ...   # same seq counter, longer namespace
```

- `seq` is strictly increasing across the recorder **and all its children** (shared counter).
- `ts` comes from the `Clock`, never `datetime.now()`.

### 6.2 `EventBus` and sinks

```python
class EventSink(Protocol):
    name: str
    async def handle(self, event: Event) -> None: ...

class EventBus:
    def __init__(self, sinks: Sequence[EventSink]) -> None: ...
    async def publish(self, event: Event) -> None: ...
```

- Delivers each event to every sink, in order.
- **A failing sink never breaks the run**: the exception is logged (sink name + event kind, no payload) and counted (`bus.failures[sink_name]`), and the other sinks still receive the event (W3 L3: a broken remote tracer must not switch off the harness).
- `MemorySink` keeps events in a list. Tests use it now; M17 builds `AgentResult` from exactly this list.

### 6.3 `JsonlSink`

- Appends one JSON line per event (`event.model_dump_json()`) to `var/events/<YYYY-MM-DD>.jsonl` (UTC date from the event's `ts`).
- `encoding="utf-8"`, `newline="\n"`, creates the directory if needed.
- File writes run in `asyncio.to_thread` so the event loop is never blocked (ruff `ASYNC` rules flag blocking `open()` in `async` code).
- An `asyncio.Lock` keeps concurrent writes from interleaving lines.

This is the "local event log always on" from architecture §8: if LangSmith/Langfuse are down or not configured, the JSONL file is still the evidence of what ran.

## 8. Contract snapshot tests (⚙️ write, 📖 understand)

`tests/contract/test_schemas.py` compares the current JSON schema of `Event`, every registered payload model and `ToolResult[dict[str, JsonValue]]` against files in `tests/contract/snapshots/`. Any schema change fails the test until the snapshot is regenerated **deliberately** (`uv run poe snapshots`, a new poe task) and the diff is reviewed in the commit.

> This turns "someone changed the event shape and the UI broke" into a red CI run with a readable diff. Pair it with the versioning rule in §5.3.

Plus behavioural tests (unit):
- `principal_for` on every seed employee gives the scopes of §2.2; G-001 (Globex) gets Globex `tenant_id`.
- `require_scope`: allow and `MISSING_SCOPE` cases.
- `ToolResult` invariants: each constructor valid; invalid combinations rejected.
- Domain error mapping: the table in §4.4; a non-domain exception is **not** swallowed.
- `Event` rejects unknown kinds, payloads that fail their model, naive datetimes.
- `RunRecorder`: `seq` 0..n across parent and children; `ts` from `FixedClock`; namespaces.
- `EventBus`: a raising sink does not stop delivery to the next sink; failure counted.
- `JsonlSink`: writes valid JSON lines, one per event, UTF-8 (include a Vietnamese string), file closed afterwards (Windows `tmp_path` cleanup).
- `redact`: nested keys, emails, truncation, input not mutated.
